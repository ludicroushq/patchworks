# Done-for-you Patchworks setup

One template. One new project. Two consecutive updates.

The founding setup is a fixed-scope engagement for a GitHub team that wants
proof on a real repository before adopting Patchworks more broadly.

## $750 one time

The engagement is complete when:

- one new project is created from one template branch with Patchworks `0.1.4`
  or newer;
- its scheduled workflow is configured with the least access it needs;
- two consecutive template commits each reach a reviewable update pull request;
- no history reset, force push, orphan-branch deletion, or hand-edit of
  `.patchworks.json` is needed between those updates; and
- you receive the exact setup, validation, and recovery commands used.

An update with unresolved `.patchworks-rejects` does not count as a successful
cycle. If the prerequisites remain available and the agreed result cannot be
completed within this scope, the setup fee is refunded.

## Included

- A read-only fit check before payment.
- Setup for one GitHub template, one branch, and one new project repository.
- The generated Patchworks configuration and version-pinned GitHub Action.
- A permissions review for public or private templates and workflow updates.
- Validation against one project test command supplied by your team.
- Two update cycles and a concise handoff for the next update.
- Fourteen days of email support for the delivered setup.

The setup is scheduled for completion within ten business days after the fit
check, repository access, validation command, and two proof changes are ready.

Your team keeps control of repository access and credentials. Never send a
token or secret by email; access is arranged only after the fit check.

## Good fit

This setup is for a **new project created from an existing template**. Before
work begins, your team needs:

- a template repository hosted on GitHub.com;
- permission to create and configure the new project repository;
- two small template changes that can be committed separately after the new
  project is created; and
- one documented command that validates the project.

Private templates are supported when your team can provide appropriately
scoped access. If template changes may modify `.github/workflows`, that access
must include Workflows write permission.

## Outside the fixed scope

- Retrofitting an existing divergent project.
- Rewriting or reconstructing template history.
- Refactoring the template or repairing unrelated CI failures.
- Resolving broad application conflicts or migrating multiple projects.
- Merging update pull requests on your behalf.
- Ongoing maintenance after the two proof updates and support window.

Your team reviews and merges the first proof pull request before the second
update cycle begins.

If the read-only fit check finds one of these conditions, no invoice is issued.
Custom work can be scoped separately only if you ask for it.
